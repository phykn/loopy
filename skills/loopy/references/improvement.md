# Improvement

Improvement makes an existing artifact better for a stated goal, such as
shorter, faster, or easier to follow, and may change behavior or meaning to get
there. The agent chooses what to change, drop, or add, so the goal, not the
current content, decides what stays.

## Define better

Turn the goal into observable criteria before editing: a task the intended user
must still complete, a measure such as length or run time, and the rules or
interfaces that must survive. If the request names no goal and the evidence does
not settle one, ask. Record the baseline on the same tasks and measures.

`Preserve` holds only what the user stated, what consumers depend on, and what
the goal needs; the rest is a candidate for change.

## Choose changes

Rank candidates by their effect on the criteria. Remove content that changes no
action or outcome for the intended user, such as history, repetition, generic
exhortation, or rules for situations that no longer occur. Resolve conflicting
rules from evidence of the intended behavior. Add only what a required task
needs, and when the goal is less, an addition must remove more burden than it
costs; a restatement or summary of nearby rules does not.

Treat every removal or change that alters what the artifact does as a behavior
change: make it when evidence supports it, record what is lost, and ask when it
is a judgment call that materially affects users. Do not drop a rule only
because it is rarely triggered when its failure is costly.

## Compare and report

Run the same tasks and measures on the result and compare them with the
baseline; a shorter or newer artifact is not better if a required task now
fails. Report behavior changes, each with what is lost, apart from wording or
structural reductions, and give the before and after measures.
