# Improvement

Improvement moves an existing artifact toward a goal, such as shorter, faster, or easier to follow, and may change behavior or meaning; the goal, not the current content, decides what stays.

## Define better

If the request names no goal and evidence does not settle one, ask. Before editing, turn the goal into observable criteria: a task the intended user must still complete, a measure such as length or run time, and the rules or interfaces that must survive; then run those tasks and measures on the current version and record the results as the baseline. `Preserve` holds only what the user stated, what consumers depend on, and what the goal needs; the rest is a candidate.

## Choose changes

Rank candidates by their effect on the criteria. Remove content that changes no action or outcome for the intended user, such as history, repetition, generic exhortation, or rules for situations that no longer occur. Resolve conflicting rules from evidence of the intended behavior. Add only what a required task needs; when the goal is less, an addition must remove more burden than it costs, which a restatement or summary does not.

Every removal or change that alters what the artifact does is a behavior change: make it when evidence supports it, record what is lost, and ask when it is a judgment call that materially affects users. Do not drop a rule only because it rarely triggers when its failure is costly.

## Compare and report

Run the same tasks and measures on the result and compare them with the baseline; a shorter or newer artifact is not better if a required task now fails. Report behavior changes, each with what is lost, apart from wording or structural reductions, and give the before and after measures.
